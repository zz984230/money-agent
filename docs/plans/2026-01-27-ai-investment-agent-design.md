# Money-Agent：A 股 AI 投研竞技场设计方案

**日期**：2026-01-27
**版本**：v1.0

---

## 1. 项目概述

### 1.1 项目定位

基于 AI-Trader 框架，打造一个面向中国 A 股市场的多 AI 模型投研辅助平台。多个 AI 模型在相同市场数据下独立分析，用户作为"裁判"对比各模型的决策逻辑，最终由用户做出投资决策。

### 1.2 核心理念

- **人机协同**：AI 提供多视角分析，用户掌握最终决策权
- **多模型竞技**：对比不同 AI 模型的分析思路，避免单一模型偏见
- **品种全面**：覆盖股票、ETF、可转债三大 A 股主要投资工具
- **本土化**：基于 AKShare、中文界面、A 股规则深度适配

### 1.3 与现有开源项目的差异

| 对比项 | AI-Trader | ai_quant_trade | TradingAgents-CN | Money-Agent |
|--------|-----------|----------------|------------------|-------------|
| 核心定位 | 零人工交易竞技 | 学习+实盘平台 | 合规研究 | 投研辅助+多AI竞技 |
| 决策权 | AI 全权决定 | 混合 | 人工 | 用户掌握最终决策 |
| 覆盖品种 | 股票、加密货币 | 股票 | 股票 | 股票+ETF+可转债 |
| 数据源 | Alpha Vantage | 多源 | 未知 | AKShare（免费） |
| 界面 | Web（英文） | Jupyter 为主 | 未知 | 中文友好仪表板 |

## 2. 系统架构

### 2.1 整体架构

```
money-agent/
├── core/                    # 核心系统（基于 AI-Trader）
│   ├── agent/              # AI 交易代理
│   │   ├── base_agent.py   # 基础代理类
│   │   └── glm_agent.py    # GLM-4.7 代理
│   ├── mcp_tools/          # MCP 工具链
│   └── prompts/            # 提示词工程
│
├── data/                   # 数据层
│   ├── fetchers/           # 数据获取（AKShare）
│   │   └── akshare_fetcher.py
│   ├── processors/         # 数据处理
│   └── storage/            # 数据存储
│
├── analysis/               # 分析层（新增）
│   ├── screening.py        # 选股筛选
│   ├── market_analysis.py  # 市场分析
│   ├── etf_analysis.py     # ETF 分析
│   ├── convertible_analysis.py  # 可转债分析
│   ├── backtest.py         # 策略回测
│   └── risk_monitor.py     # 风险监控
│
├── ui/                     # 用户界面
│   └── dashboard.py        # 可视化仪表板
│
└── config/                 # 配置文件
    └── settings.yaml
```

### 2.2 数据流设计

```
1. 数据获取层（AKShare）
   ↓ 股票列表、日线数据、财务数据、公告新闻、ETF、可转债
2. 数据处理层
   ↓ 清洗、标准化、特征工程
3. AI 分析层
   ↓ 多模型并行分析
4. 决策支持层
   ↓ 结果汇总、对比展示
5. 用户决策层
   ↓ 用户查看分析结果，做出决策
6. 执行与记录层
   ↓ 记录决策、跟踪效果
```

## 3. 核心功能模块

### 3.1 选股筛选模块

**功能**：从全 A 股市场筛选符合条件的股票

**筛选维度**：
- 技术面：均线形态、RSI、MACD、成交量等
- 基本面：PE/PB、ROE、营收增速等
- 市场热点：概念板块、资金流向

**AI 竞技方式**：每个 AI 模型根据相同的筛选条件，给出各自的选股结果和理由

### 3.2 行业 ETF 分析模块

**功能**：行业/主题/宽基 ETF 的筛选与分析

**覆盖范围**：
- 主要行业 ETF：半导体、新能源、医药、消费、金融等
- 主题 ETF：红利、科创、创业板等
- 宽基 ETF：沪深300、中证500、中证1000等

**分析维度**：
- 行业景气度与政策导向
- ETF 规模与流动性
- 持仓集中度与权重股表现
- 技术形态与资金流向

**AI 竞技方式**：各模型分析不同行业的配置价值，给出 ETF 配置建议

### 3.3 可转债分析模块

**功能**：可转债筛选与投资分析

**覆盖范围**：全市场可转债（含已上市、待上市）

**分析维度**：
- **债底保护**：转债价格、纯债价值、到期收益率
- **股性弹性**：转股溢价率、正股走势、换手率
- **条款博弈**：强赎条款、下修条款、回售条款
- **估值水平**：转股溢价率、纯债溢价率、双低值

**筛选策略**：
- 双低策略（价格低 + 溢价率低）
- 高弹性策略（低溢价 + 正股活跃）
- 打新策略（新债申购分析）
- 条款博弈策略（临近强赎、下修预期）

### 3.4 市场分析模块

**功能**：生成市场、行业、个股、ETF、可转债分析报告

**分析层次**：
- 大盘分析：指数走势、市场情绪、资金面
- 行业分析：板块轮动、行业景气度
- 个股分析：财务数据、技术形态、事件驱动
- ETF 分析：行业配置价值、风格轮动
- 可转债分析：转股价值、条款分析、机会挖掘

**AI 竞技方式**：多个 AI 同时分析同一标的，用户对比不同视角

### 3.5 策略回测模块

**功能**：验证交易策略在历史数据上的表现

**核心能力**：
- 支持 个股 + ETF + 可转债 组合回测
- 计算收益率、最大回撤、夏普比率等指标
- 生成回测报告和可视化图表

### 3.6 风险监控模块

**功能**：实时预警潜在风险

**监控指标**：
- 持仓集中度风险（个股 + ETF + 可转债）
- 市场系统性风险
- 行业轮动风险
- 转债特定风险：强赎风险、正股退市风险、信用风险
- 个股异常波动、公告新闻事件提醒

## 4. 技术实现方案

### 4.1 技术栈选型

**后端框架**：
- Python 3.10+：主要开发语言
- FastAPI：Web 服务框架（用于 MCP 工具链和 API）
- LangChain/LangGraph：AI Agent 编排框架（继承自 AI-Trader）
- MCP (Model Context Protocol)：标准化工具接口（继承自 AI-Trader）

**数据层**：
- AKShare：主要数据源（开源免费）
- 备用数据源：Tushare、efinance（按需接入）
- 存储：JSONL（继承 AI-Trader 格式）+ SQLite（结构化数据）

**AI 模型接入**：
- GLM-4.7（智谱 AI）：主力模型
- 预留接口：Qwen、DeepSeek、Claude、GPT-4
- 模型调用：通过统一 Adapter 封装，便于扩展

**前端界面**：
- Streamlit：快速构建 Web 仪表板
- Plotly：交互式图表
- Bootstrap：UI 组件库

### 4.2 与 AI-Trader 的集成方案

**复用部分**：
- MCP 工具链框架
- Agent 基础架构
- 回测引擎
- 数据格式规范

**新增/修改部分**：
- 数据获取：从 Alpha Vantage 改为 AKShare
- Agent 提示词：优化为投研辅助场景
- 分析模块：新增选股、ETF、可转债分析
- 用户交互：增加人工决策节点
- 可视化：更友好的中文界面

## 5. 典型工作流程

### 5.1 每日选股流程

1. 系统从 AKShare 获取最新市场数据
2. 用户设定筛选条件（如：PE < 30，营收增速 > 20%）
3. 多个 AI 模型各自分析，给出候选股票池
4. 用户对比各模型的选择逻辑和结果
5. 用户决定是否采纳某个模型的建议

### 5.2 个股/ETF/可转债分析流程

1. 用户指定要分析的标的代码
2. AI 模型各自生成分析报告
3. 系统汇总各模型观点，标注一致性和分歧点
4. 用户基于综合分析做出判断

### 5.3 策略回测流程

1. 用户定义交易策略（如：双均线、突破策略）
2. 系统在历史数据上回测
3. AI 分析回测结果，指出策略优缺点
4. 用户决定是否优化或采用该策略

## 6. 开发计划

### 阶段一：基础框架搭建（Week 1-2）
- 初始化项目结构
- 集成 AKShare 数据源
- 搭建基础 Agent 框架（参考 AI-Trader）
- 实现 GLM-4.7 模型接入
- **里程碑**：能获取 A 股基础数据，AI 能进行简单对话

### 阶段二：核心分析功能（Week 3-4）
- 实现选股筛选模块
- 实现市场分析模块
- 实现个股分析功能
- **里程碑**：AI 能生成基础的个股分析报告

### 阶段三：扩展品种支持（Week 5-6）
- 实现 ETF 分析模块
- 实现可转债分析模块
- 支持多品种组合分析
- **里程碑**：覆盖股票、ETF、可转债三大品种

### 阶段四：策略回测与风控（Week 7-8）
- 集成/开发回测引擎
- 实现风险监控模块
- 优化 AI 提示词工程
- **里程碑**：完整的回测和风控功能

### 阶段五：界面与优化（Week 9-10）
- 开发 Web 仪表板
- 实现多 AI 模型竞技展示
- 性能优化与 bug 修复
- **里程碑**：可用的 MVP 版本

## 7. 技术风险评估

| 风险项 | 风险描述 | 缓解措施 |
|--------|----------|----------|
| 数据质量 | AKShare 数据可能有延迟或缺失 | 备用 Tushare |
| 模型成本 | GLM-4.7 API 调用费用 | 优化 prompt，考虑本地模型 |
| 回测准确性 | 复用 AI-Trader 引擎但需验证 A 股规则 | 充分测试 |
